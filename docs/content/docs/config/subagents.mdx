Subagents use our Pi-in-Pi architecture located in `@pi-ohm/core/pip`. Use `/subagents` in Pi to inspect integrated agents and custom configured agents in a non-model-facing TUI widget.

## Built-in

Ohm comes with three integrated subagents.

### Librarian

multi-repository codebase understanding and explanation

### Oracle

reasoning-heavy review, planning, debugging, and architecture advice

### Finder

behavior-based code search for concepts, flows, and broad terms

## JSON

Configure agents in your ohm.json config file:

```json title="ohm.json"
{
  "subagents": {
    "librarian": {
      "disabled": false,
      "model": "openai-codex/gpt-5.4-mini:medium",
      "tools": ["read", "grep", "find"],
      "maxTurns": 12,
      "description": "Answer deep codebase questions with thorough explanations.",
      "prompt": "You are Librarian. Read broadly before answering. Return complete explanations.",
      "permissions": {
        "read": "allow",
        "grep": "allow",
        "find": "allow",
        "bash": "deny"
      }
    },

    "oracle": {
      "model": "openai-codex/gpt-5.4-mini:high",
      "tools": ["read", "grep"],
      "description": "Use for architecture review, complex debugging, planning, and correctness checks.",
      "prompt": "You are Oracle. Focus on correctness, design, risk, and hard tradeoffs."
    },

    "finder": {
      "tools": ["read", "grep", "find"],
      "description": "Use for finding code by behavior, broad concepts, flows, or related paths.",
      "prompt": "You are Finder. Search precisely and return paths with concise notes."
    },

    "reviewer": {
      "disabled": false,
      "description": "Use for reviewing diffs and checking implementation quality.",
      "prompt": "Find correctness, type safety, and design issues.",
      "tools": ["read", "grep", "bash"],
      "permissions": {
        "bash": "deny",
        "read": "allow",
        "grep": "allow"
      },
      "variants": {
        "*gpt-5.4-mini*": {
          "description": "Use for quick actionable review on gpt-5.4-mini.",
          "prompt": "Review quickly. Report only actionable issues.",
          "tools": ["read", "grep"],
          "permissions": {
            "bash": "inherit",
            "grep": "deny"
          }
        },
        "*experimental*": {
          "disabled": true
        }
      }
    }
  }
}
```

Important behavior:

- `subagents.<name>` is the only JSON agent shape. There is no `subagents.profiles` fallback.
- There are no backend/runtime switching options. Subagents always use the Pi SDK PiP runner.
- `description` is the model-facing guidance for when to use an agent.
- `disabled: true` keeps the agent visible in the user-only `/subagents` UI, but model-facing tools treat it as unavailable.
- Disabled agents are not exposed to the main model as usable options, and their configured prompts are never included in tool results.
- If `model` is omitted, the subagent inherits the current main session model.
- `model` accepts `<provider>/<model>` with optional `:<thinking>`.
- Configure thinking in config through the model suffix, for example `openai-codex/gpt-5.4-mini:high`.
- Known models resolve through Pi's model registry and Pi AI built-ins.
- Custom providers from `models.json` or provider extensions are allowed.
- Unknown providers pass through as external models.
- `permissions` values are `allow`, `deny`, `inherit`, or legacy `ask`. Legacy `ask` becomes `deny`.
- Denied tools are removed from the child session `tools` allowlist.
- Variant keys are lowercase wildcard patterns matched against `<provider>/<model>` and `<model>`.

Model precedence:

1. `spawn_agent.model` and `spawn_agent.thinking`
2. agent `model`, including optional `:<thinking>` suffix
3. current main session model and thinking, when no agent model is configured
4. fallback default only when Pi has no active model

## Markdown

Markdown agent files are the intended authoring shape for richer agents. They should live in one of these locations:

```txt
.pi/agents/<name>.md
${PI_CONFIG_DIR|PI_CODING_AGENT_DIR|PI_AGENT_DIR|~/.pi/agent}/agents/<name>.md
```

Example:

```md title=".pi/agents/reviewer.md"
---
disabled: false
model: openai-codex/gpt-5.4-mini:medium
tools:
  - read
  - grep
  - bash
maxTurns: 12
description: Use for reviewing diffs and checking implementation quality.
permissions:
  bash: deny
  read: allow
  grep: allow
variants:
  "*gpt-5.4-mini*":
    description: Use for quick actionable review on gpt-5.4-mini.
    tools:
      - read
      - grep
    permissions:
      bash: inherit
      grep: deny
  "*experimental*":
    disabled: true
---

You are Reviewer.

Find correctness, type safety, and design issues. Prefer concrete file references and avoid style nitpicks unless they hide a real defect.
```

Another custom agent:

```md title=".pi/agents/security-reviewer.md"
---
description: Use for auth, permission, injection, and secret-handling reviews.
tools:
  - read
  - grep
permissions:
  read: allow
  grep: allow
  bash: deny
---

Find auth, injection, secret handling, and permission bugs. Return only issues with exploitability or clear risk.
```

Markdown support is planned as the agent-file layer described above. Today, JSON config is the source of truth implemented by the subagents package.
