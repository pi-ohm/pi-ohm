---
title: Subagents
description: Configure Pi-backed subagents with JSON or markdown profiles.
---

Subagents are Pi-backed child sessions. Use `/subagents` in Pi to inspect integrated agents and custom configured agents in a non-model-facing TUI widget.

Ohm reads config from:

1. global config: `${PI_CONFIG_DIR|PI_CODING_AGENT_DIR|PI_AGENT_DIR|~/.pi/agent}/ohm.json`
2. project config: `<cwd>/.pi/ohm.json`

Project config overrides global config. Spawn args override config for one run.

Integrated subagents always exist:

- `librarian` - multi-repository codebase understanding and explanation
- `oracle` - reasoning-heavy review, planning, debugging, and architecture advice
- `finder` - behavior-based code search for concepts, flows, and broad terms

## JSON

Use `.pi/ohm.json` for project config, or `ohm.json` in the global Ohm config dir.

```json title=".pi/ohm.json"
{
  "subagents": {
    "backend": "interactive-sdk",
    "taskMaxConcurrency": 3,
    "taskRetentionMs": 86400000,
    "permissions": {
      "default": "allow",
      "subagents": {
        "oracle": "allow",
        "experimental-reviewer": "deny"
      },
      "allowInternalRouting": false
    },

    "librarian": {
      "disabled": false,
      "model": "openai-codex/gpt-5.4-mini:medium",
      "thinking": "medium",
      "tools": ["read", "grep", "find"],
      "maxTurns": 12,
      "description": "Answer deep codebase questions with thorough explanations.",
      "prompt": "You are Librarian. Read broadly before answering. Return complete explanations.",
      "whenToUse": [
        "understanding large codebases",
        "tracing architecture across files",
        "explaining existing behavior"
      ],
      "permissions": {
        "read": "allow",
        "grep": "allow",
        "find": "allow",
        "bash": "deny"
      }
    },

    "oracle": {
      "model": "openai-codex/gpt-5.4-mini:high",
      "thinking": "high",
      "tools": ["read", "grep"],
      "description": "Reasoning-heavy reviewer and planner.",
      "prompt": "You are Oracle. Focus on correctness, design, risk, and hard tradeoffs.",
      "whenToUse": [
        "reviewing architecture",
        "debugging complex behavior",
        "planning non-trivial changes"
      ]
    },

    "finder": {
      "tools": ["read", "grep", "find"],
      "description": "Find code by behavior or concept.",
      "prompt": "You are Finder. Search precisely and return paths with concise notes.",
      "whenToUse": [
        "locating code by behavior",
        "correlating related code paths",
        "narrowing broad search terms"
      ]
    },

    "reviewer": {
      "disabled": false,
      "description": "Strict code reviewer",
      "prompt": "Find correctness, type safety, and design issues.",
      "whenToUse": ["review diffs", "check implementation quality"],
      "tools": ["read", "grep", "bash"],
      "permissions": {
        "bash": "deny",
        "read": "allow",
        "grep": "allow"
      },
      "variants": {
        "*gpt-5.4-mini*": {
          "thinking": "minimal",
          "prompt": "Review quickly. Report only actionable issues.",
          "tools": ["read", "grep"],
          "permissions": {
            "bash": "inherit",
            "grep": "deny"
          }
        },
        "*experimental*": {
          "disabled": true
        }
      }
    }
  }
}
```

You can also put custom agents under `subagents.profiles` if you prefer keeping runtime keys and profiles separate:

```json title=".pi/ohm.json"
{
  "subagents": {
    "backend": "interactive-sdk",
    "profiles": {
      "security-reviewer": {
        "description": "Security-focused reviewer",
        "prompt": "Find auth, injection, secret handling, and permission bugs.",
        "tools": ["read", "grep"],
        "whenToUse": ["review security-sensitive changes"]
      }
    }
  }
}
```

Important behavior:

- `disabled: true` keeps the profile visible in the user-only `/subagents` UI, but model-facing tools treat it as unavailable.
- Disabled profiles are not exposed to the main model as usable options, and their configured prompts are never included in tool results.
- If `model` is omitted, the subagent inherits the current main session model.
- If `thinking` is omitted, the subagent inherits the current main session thinking level.
- `model` accepts `<provider>/<model>` with optional `:<thinking>`.
- Known models resolve through Pi's model registry and Pi AI built-ins.
- Custom providers from `models.json` or provider extensions are allowed.
- Unknown providers pass through as external models.
- `permissions` values are `allow`, `deny`, `inherit`, or legacy `ask`. Legacy `ask` becomes `deny`.
- Denied tools are removed from the child session `tools` allowlist.
- Variant keys are lowercase wildcard patterns matched against `<provider>/<model>` and `<model>`.

Model precedence:

1. `spawn_agent.model` and `spawn_agent.thinking`
2. profile `model` and `thinking`
3. current main session model and thinking
4. fallback default only when Pi has no active model

## Markdown

Markdown agent files are the intended authoring shape for richer agents. They should live in one of these locations:

```txt
.pi/agents/<name>.md
${PI_CONFIG_DIR|PI_CODING_AGENT_DIR|PI_AGENT_DIR|~/.pi/agent}/agents/<name>.md
```

Example:

```md title=".pi/agents/reviewer.md"
---
disabled: false
model: openai-codex/gpt-5.4-mini:medium
thinking: high
tools:
  - read
  - grep
  - bash
maxTurns: 12
description: Strict code reviewer
whenToUse:
  - review diffs
  - check implementation quality
permissions:
  bash: deny
  read: allow
  grep: allow
variants:
  "*gpt-5.4-mini*":
    thinking: minimal
    tools:
      - read
      - grep
    permissions:
      bash: inherit
      grep: deny
  "*experimental*":
    disabled: true
---

You are Reviewer.

Find correctness, type safety, and design issues. Prefer concrete file references and avoid style nitpicks unless they hide a real defect.
```

Another custom agent:

```md title=".pi/agents/security-reviewer.md"
---
description: Security-focused reviewer
tools:
  - read
  - grep
whenToUse:
  - review auth changes
  - review permission-sensitive code
permissions:
  read: allow
  grep: allow
  bash: deny
---

Find auth, injection, secret handling, and permission bugs. Return only issues with exploitability or clear risk.
```

Markdown support is planned as the profile-file layer described above. Today, JSON config is the source of truth implemented by the subagents package.
